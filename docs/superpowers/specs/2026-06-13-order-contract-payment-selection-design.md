# 第二轮订单合同付款选位闭环设计

## 1. 目标

第二轮建设目标是在 foundation 基础上形成可演示、可继续扩展的核心业务闭环：

```text
面积档位/价格维护
-> 展商下单
-> 销售确认订单
-> 生成合同版本
-> 财务确认付款
-> 开放选位资格
-> 展商提交选位
-> 展位锁定
-> 后台审核确认
```

本轮采用“最小完整闭环”方案，并纳入选位驳回和锁位超时释放接口位。实现重点是状态机、事务一致性和页面可操作性，不扩展到服务中心、发票、退款、合同变更和完整 RBAC。

## 2. 本轮范围

### 2.1 纳入范围

- 面积档位基础维护。
- 价格规则基础维护。
- 展商下单页：选择展会、展区或品类、标准面积档位，系统计算金额。
- 参展订单创建、查询和销售确认。
- 合同主记录和 `contract_versions` v1 快照生成。
- 付款记录创建和财务确认。
- 订单付款聚合：根据已确认付款金额更新订单状态和选位资格。
- 展商选位：按订单选择一个或多个展位，面积合计必须严格等于订单面积档位。
- 选位提交：事务内锁定展位、创建选位申请和锁定记录。
- 选位审核通过：展位从锁定中变为已确认。
- 选位驳回：选位申请进入已驳回，展位释放为可选，订单选位资格回到可选位。
- 锁位超时释放接口位：提供后端服务方法和接口，后续可由定时任务调用；本轮不要求调度器真实周期执行。
- 前端页面：档位维护、价格维护、展商下单、订单管理、销售确认入口、合同管理、付款确认、展商选位、选位审核。

### 2.2 暂不纳入

- 展商注册、登录和完整身份体系。
- 报名审核完整流程。
- 电子签章平台对接。
- 线上支付渠道和支付回调。
- 退款、冲正和展位释放待办完整处理。
- 合同变更和多版本变更审批。
- 服务中心、服务订单、发票、通知。
- 完整 RBAC、菜单权限和数据权限。
- 复杂可视化展位图编辑器。

## 3. 明确约束

### 3.1 面积严格相等

选位提交时，所选展位面积合计必须严格等于订单的标准面积档位面积。

规则：

- 合计面积小于订单面积：禁止提交。
- 合计面积大于订单面积：禁止提交。
- 多个展位可组合，但总面积必须精确匹配。
- 面积使用 `BigDecimal` 计算，统一按 `numeric(14,2)` 持久化，不使用浮点数。

### 3.2 付款聚合算法位置

付款聚合算法放在后端 `payment` 应用服务层，作为财务确认付款的事务内步骤。

聚合规则：

```text
confirmed_amount = sum(payments.amount where status = 已确认 and order_id = 当前订单)

if confirmed_amount >= participation_orders.total_amount:
    order.status = 已付款
    selection_eligibility.status = 可选位
elif confirmed_amount > 0:
    order.status = 部分付款
    selection_eligibility.status = 未开放
else:
    order.status = 待付款
    selection_eligibility.status = 未开放
```

本轮不扣减退款金额，因为退款流程不在第二轮实现。后续退款实现时，聚合算法扩展为“已确认付款净额 = 已确认付款金额 - 已完成退款金额”。

### 3.3 展商身份临时写死

本轮不做登录认证。展商端 API 和页面使用临时固定展商身份：

```text
demo exhibitorId = 00000000-0000-0000-0000-000000000001
```

要求：

- 后端允许请求显式传入 `exhibitorId`，默认页面使用上述固定值。
- 代码中集中定义默认展商 ID，不在多个页面和服务中散落硬编码。
- 后续接入认证后，以登录用户身份替换该固定值。

### 3.4 锁位超时释放接口位

本轮实现超时释放的服务方法和 API，不要求定时任务自动周期执行。

接口位行为：

- 扫描或指定处理已过 `lock_expires_at` 且状态为待审核的选位申请。
- 在事务内将选位申请置为已超时。
- 将关联展位从锁定中恢复为可选。
- 将订单选位资格恢复为可选位。
- 写入审计日志。

## 4. 状态转移映射表

### 4.1 参展订单 ParticipationOrder.status

| 当前状态 | 事件 | 下一状态 | 责任角色 | 同步动作 |
| --- | --- | --- | --- | --- |
| 待销售确认 | 销售确认订单 | 待签合同 | 销售/管理员 | 生成合同主记录和 v1 合同版本 |
| 待签合同 | 合同标记已生成/待付款 | 待付款 | 系统/销售 | 初始化付款入口 |
| 待付款 | 财务确认部分金额 | 部分付款 | 财务 | 选位资格保持未开放 |
| 待付款/部分付款 | 财务确认金额满足订单总价 | 已付款 | 财务 | 选位资格变为可选位 |
| 已付款 | 选位提交待审核 | 已付款 | 展商 | 选位资格变为暂停中 |
| 已付款 | 展会归档或管理员完成归档 | 已完成 | 管理员 | 本轮只保留状态入口，不实现归档页 |

### 4.2 付款 Payment.status

| 当前状态 | 事件 | 下一状态 | 责任角色 | 同步动作 |
| --- | --- | --- | --- | --- |
| 待财务确认 | 财务确认到账 | 已确认 | 财务 | 执行订单付款聚合 |
| 待财务确认 | 财务确认失败 | 确认失败 | 财务 | 记录失败原因 |

本轮线下付款记录创建后直接进入“待财务确认”。线上支付和回调不在本轮实现。

### 4.3 选位资格 SelectionEligibility.status

| 当前状态 | 事件 | 下一状态 | pause_reason | 同步动作 |
| --- | --- | --- | --- | --- |
| 未开放 | 订单付款聚合达到已付款 | 可选位 | 空 | 展商可进入选位 |
| 可选位 | 提交选位申请 | 暂停中 | selection_pending | 禁止同订单再提交有效申请 |
| 暂停中 | 选位审核通过 | 已关闭 | 空 | 订单已完成展位确认 |
| 暂停中 | 选位驳回 | 可选位 | 空 | 展商可重新选位 |
| 暂停中 | 锁位超时释放 | 可选位 | 空 | 展商可重新选位 |

### 4.4 选位申请 BoothSelection.status

| 当前状态 | 事件 | 下一状态 | 责任角色 | 同步动作 |
| --- | --- | --- | --- | --- |
| 草稿 | 提交选位 | 待审核 | 展商 | 锁定展位，生成 BoothLock |
| 待审核 | 审核通过 | 已确认 | 销售/管理员 | 展位变为已确认 |
| 待审核 | 审核驳回 | 已驳回 | 销售/管理员 | 展位释放为可选，资格回到可选位 |
| 待审核 | 锁位超时 | 已超时 | 系统/管理员接口 | 展位释放为可选，资格回到可选位 |

本轮可以不实现草稿持久化页面。若直接提交选位，后端可在事务内创建待审核申请。

### 4.5 展位 Booth.status

| 当前状态 | 事件 | 下一状态 | 同步对象 |
| --- | --- | --- | --- |
| 可选 | 选位提交 | 锁定中 | BoothSelection、BoothLock |
| 锁定中 | 选位审核通过 | 已确认 | BoothSelection、BoothLock |
| 锁定中 | 选位驳回 | 可选 | BoothSelection、BoothLock |
| 锁定中 | 锁位超时释放 | 可选 | BoothSelection、BoothLock |

## 5. 后端设计

### 5.1 模块

第二轮新增或补强后端模块：

```text
pricing
order
contract
payment
selection
```

保留 foundation 的 `event`、`booth`、`audit`、`common`。

### 5.2 面积档位与价格

面积档位 `area_tiers`：

- 关联 `event_id`。
- 可选关联 `zone_id`。
- 保存 `area_sqm` 和 `enabled`。

价格规则 `price_rules`：

- 关联 `event_id`。
- 可选关联 `zone_id`。
- 保存 `booth_type`、`unit_price`、`enabled`。

下单时按订单所选展区/展位类型匹配价格规则。本轮若没有展区配置，可使用 event 级默认价格规则。

### 5.3 参展订单

创建订单输入：

- `eventId`
- `exhibitorId`
- `zoneId` 可选
- `areaTierId`
- `boothType`

创建规则：

- 面积档位必须启用。
- 价格规则必须存在且启用。
- `area_fee = area_tier.area_sqm * unit_price`
- `service_fee = 0`
- `discount_amount = 0`
- `adjustment_amount = 0`
- `total_amount = area_fee`
- 初始状态为 `待销售确认`
- 同时创建 `selection_eligibilities`，状态为 `未开放`

销售确认规则：

- 订单必须处于 `待销售确认`。
- 确认后订单进入 `待签合同`。
- 系统生成 `contracts` 主记录和 `contract_versions` v1 快照。
- 合同 v1 快照包含订单金额、面积、展会、展商、状态和创建人。
- 本轮可将合同签署简化为后台标记合同已生成，然后订单进入 `待付款`。

### 5.4 付款

创建付款记录：

- 关联订单。
- 记录金额、方式、状态。
- 本轮支持线下转账方式，状态进入 `待财务确认`。

财务确认付款：

- 付款必须处于 `待财务确认`。
- 财务确认后付款进入 `已确认`。
- 在同一事务内执行订单付款聚合。
- 若订单进入 `已付款`，同步选位资格为 `可选位`。
- 写审计日志。

### 5.5 选位提交

选位提交输入：

- `orderId`
- `exhibitorId`
- `boothIds`

提交规则：

- 订单必须属于该展商。
- 订单状态必须为 `已付款`。
- 选位资格必须为 `可选位`。
- 同一订单不能存在待审核选位申请。
- 所选展位必须全部属于订单展会。
- 所选展位必须全部为 `可选`。
- 面积合计必须严格等于订单面积档位。
- 在事务内锁定相关 booth 行。
- 创建 `booth_selections`，状态为 `待审核`。
- 创建 `booth_locks`。
- 更新 booth 状态为 `锁定中`。
- 更新选位资格为 `暂停中`，`pause_reason = selection_pending`。
- 写审计日志。

### 5.6 选位审核

审核通过：

- 选位申请必须为 `待审核`。
- 关联展位必须为 `锁定中`。
- 选位申请进入 `已确认`。
- 关联展位进入 `已确认`。
- BoothLock 状态更新为 confirmed。
- 选位资格进入 `已关闭`。
- 写审计日志。

审核驳回：

- 选位申请必须为 `待审核`。
- 必须填写驳回原因。
- 选位申请进入 `已驳回`。
- 关联展位恢复为 `可选`。
- BoothLock 状态更新为 rejected 或 released。
- 选位资格回到 `可选位`。
- 写审计日志。

超时释放：

- 选位申请必须为 `待审核`。
- 当前时间必须大于 `lock_expires_at`，或由管理员以超时处理接口触发。
- 选位申请进入 `已超时`。
- 关联展位恢复为 `可选`。
- BoothLock 状态更新为 timeout_released。
- 选位资格回到 `可选位`。
- 写审计日志。

## 6. 前端设计

前端必须继续使用 Ant Design 和 ProComponents，不自造基础表格、表单和弹窗组件。

### 6.1 后台页面

本轮新增后台页面：

```text
面积档位维护
价格规则维护
订单管理
合同管理
付款确认
选位审核
```

页面职责：

- 面积档位维护：使用 ProTable + ModalForm，维护 event 级或 zone 级档位。
- 价格规则维护：使用 ProTable + ModalForm，维护单价。
- 订单管理：展示订单状态、金额、面积档位，提供销售确认入口。
- 合同管理：展示合同和版本快照。
- 付款确认：展示待财务确认付款，提供确认/失败入口。
- 选位审核：展示待审核选位申请、所选展位、面积合计、锁位截止时间，提供通过/驳回/超时释放操作。

### 6.2 展商端页面

本轮新增展商端页面：

```text
展商下单页
我的订单
付款提交页
选位页面
选位结果页
```

页面职责：

- 展商下单页：选择展会、面积档位和展位类型，展示金额计算结果并提交订单。
- 我的订单：展示订单状态、合同状态、付款状态和可选位入口。
- 付款提交页：提交线下付款记录。
- 选位页面：使用 ProTable 展示可选展位，支持多选，实时显示已选面积和应选面积。
- 选位结果页：展示待审核、已确认、已驳回、已超时状态。

### 6.3 展商身份

展商端页面统一使用临时固定展商 ID：

```text
00000000-0000-0000-0000-000000000001
```

该值集中放在前端 auth 或 demo context 文件中。后续接入登录后替换。

## 7. API 设计

建议 API：

```text
GET    /api/area-tiers?eventId=
POST   /api/area-tiers
GET    /api/price-rules?eventId=
POST   /api/price-rules

POST   /api/participation-orders
GET    /api/participation-orders?eventId=&exhibitorId=&status=
POST   /api/participation-orders/{orderId}/confirm

GET    /api/contracts?orderId=
GET    /api/contracts/{contractId}/versions

POST   /api/payments
GET    /api/payments?orderId=&status=
POST   /api/payments/{paymentId}/confirm
POST   /api/payments/{paymentId}/fail

GET    /api/selection-eligibilities?orderId=
POST   /api/booth-selections
GET    /api/booth-selections?orderId=&status=
POST   /api/booth-selections/{selectionId}/approve
POST   /api/booth-selections/{selectionId}/reject
POST   /api/booth-selections/{selectionId}/timeout-release
```

所有写接口保留 `requestId` 或 `clientToken` 参数位。本轮可先记录字段或方法参数，后续幂等表统一实现时接入。

## 8. 事务与并发

必须在一个事务内完成：

- 销售确认订单 + 生成合同。
- 财务确认付款 + 付款聚合 + 选位资格更新。
- 选位提交 + 展位锁定 + 资格暂停 + 审计日志。
- 选位审核通过 + 展位确认 + 锁定记录更新 + 资格关闭。
- 选位驳回 + 展位释放 + 锁定记录更新 + 资格恢复。
- 锁位超时释放 + 展位释放 + 锁定记录更新 + 资格恢复。

选位提交必须对所选 booth 行加锁，避免并发重复锁定。本轮以 PostgreSQL 行级锁为准，Redis 辅助锁可留到后续。

## 10. 风险与后续衔接

- 本轮使用固定展商 ID，后续必须接入真实认证和数据权限。
- 本轮不实现报名审核，因此订单可选展区/品类暂不受报名结果约束；后续报名模块接入后必须补上约束。
- 本轮合同只生成版本快照，不做电子签署；后续合同签署方式确认后扩展。
- 本轮超时释放由接口触发，后续调度器接入后周期执行。
- 本轮不处理退款，后续退款完成后应触发展位释放待办。
