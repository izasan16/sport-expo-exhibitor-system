# 展馆场景编辑器真实底图可用性整改设计

## 1. 目标

在不重构现有场景编辑器架构的前提下，把“真实展馆底图进入系统后能顺畅查看、拖动、缩放、审核”的关键体验补齐。

本轮只处理以下问题：

- 上传真实底图时后端上限过小，出现 `413`
- 前端上传前没有明确大小提示
- 编辑器无法在真实底图下进行稳定的视口控制
- 审核预览页只能静态看图，无法缩放和平移
- 右侧信息面板会被长文件名和长修订号挤坏

本轮目标不是重做绘图能力，而是把“真实底图可用”这一层打牢。

## 2. 范围

### 2.1 本轮范围

- 后端文件上传上限调整为 `10MB`
- 前端上传控件增加文件类型与大小提示
- 前端上传前做文件大小校验
- 场景编辑器补充统一视口能力：
  - 自动适配画布
  - 放大
  - 缩小
  - 拖拽平移
  - 重置视图
- 选位审核预览页补充只读视口能力：
  - 自动适配画布
  - 放大
  - 缩小
  - 拖拽平移
  - 重置视图
- 右侧信息区宽度稳定化
- 文件名与修订号做省略显示和完整信息提示

### 2.2 本轮非范围

- 不引入新的重型画布库替换现有 SVG 方案
- 不做 CAD / DWG 原生解析
- 不做底图裁切、旋转、图层识别
- 不做鼠标滚轮连续缩放的高阶交互优化作为硬要求
- 不做移动端触摸手势优化，例如双指缩放、单指惯性平移
- 不做场景编辑器整体 UI 重构

说明：

- 后台编辑器本轮仍以桌面端为主
- 审核预览页若在移动端访问，可接受降级为“按钮缩放 + 只读查看”，不承诺复杂触摸手势体验

## 3. 设计原则

- 保持当前“业务壳 + 轻量 SVG 画布”的实现方向，不做架构跳变
- 所有视口控制都只影响展示视图，不改真实几何坐标
- 编辑器与审核预览页共享同一套视口计算模型，避免两套行为漂移
- 默认进入页面时自动适配真实底图或要素边界，避免用户第一次看到局部残片
- 长文本不允许破坏布局，信息不丢失但默认要克制显示

## 4. 上传整改

### 4.1 后端约束

上传上限统一调整为 `10MB`。

建议同时设置：

- `spring.servlet.multipart.max-file-size=10MB`
- `spring.servlet.multipart.max-request-size=10MB`

目标：

- 官方展馆 PDF 导出后的轻量 PNG / JPG / SVG 能顺利上传
- 避免当前 `1.4MB` 真实底图直接被 `413` 拦截的问题

### 4.2 前端约束

上传按钮附近增加明确说明：

- 支持：`PNG / JPG / SVG / PDF`
- 最大：`10MB`

上传前先做前端校验：

- 若 `file.size > 10MB`
- 直接提示：`底图文件不能超过 10MB，请压缩后重试`
- 不发起上传请求

### 4.3 错误表现

如果后端仍返回上传失败：

- 保持现有 request 错误链路
- 前端补一条更贴近业务的 message：
  - `底图上传失败，请检查文件格式或大小限制`

## 5. 统一视口模型

### 5.1 新增视口状态

前端为场景画布引入统一视口状态：

- `zoom`
- `panX`
- `panY`
- `isPanning`

可选辅助字段：

- `minZoom`
- `maxZoom`

推荐默认范围：

- `minZoom = 0.25`
- `maxZoom = 4`

### 5.2 视口语义

- `zoom=1` 表示基础画布比例
- `panX/panY` 表示当前视图相对基础画布的平移偏移
- 视口变换只作用于渲染层容器
- 所有点击坐标换算必须回到原始场景坐标系后再进入业务逻辑

实现方式采用 SVG `viewBox` 方案，而不是外层 CSS `transform` 方案。

推荐形式：

```tsx
<svg viewBox={`${viewMinX} ${viewMinY} ${viewWidth} ${viewHeight}`}>
  {/* background + features */}
</svg>
```

原因：

- 与当前轻量 SVG 方案天然一致，不需要替换底层渲染方式
- 视口状态是声明式的，适合 `fit-to-canvas` 和 `reset-view`
- 点击坐标换算更稳定，不需要额外处理 CSS transform 叠加误差
- 背景图和图元会天然保持同一坐标体系

`panX/panY/zoom` 最终需要换算成：

- `viewMinX`
- `viewMinY`
- `viewWidth`
- `viewHeight`

即：

- 视图平移通过调整 `viewMinX/viewMinY` 完成
- 视图缩放通过调整 `viewWidth/viewHeight` 完成

### 5.3 自动适配画布

页面首次加载、切换到底图、切换到历史版本预览时，默认执行一次 `fit-to-canvas`。

适配目标：

- 若存在背景图，则优先以背景图完整进入可视区
- 若没有背景图但有图形，则以全部图形外包框进入可视区
- 若既无背景图也无图形，则保持默认视图

适配结果：

- 整体内容完整可见
- 保留少量边距，避免紧贴容器边缘

### 5.4 重置视图

`重置视图` 行为：

- 清空当前用户对缩放和平移的临时操作
- 回到当前内容的自动适配结果

这里的“重置”不是回到固定 `100%`，而是回到“适配当前内容”的基准视图。

## 6. 编辑器交互整改

### 6.1 工具栏新增能力

编辑器顶部工具栏增加：

- `适配画布`
- `放大`
- `缩小`
- `重置视图`

保留现有：

- 上传底图
- 校准比例尺
- 保存草稿
- 校验
- 发布历史
- 发布

### 6.2 拖拽平移

中间画布支持拖拽平移。

交互规则：

- 非绘制态、非校准态下允许按住画布拖动视图
- 绘制态和校准态优先保留点选行为，不进入拖拽平移
- 平移过程中不改变图元真实坐标

### 6.3 缩放

本轮至少保证按钮缩放可用：

- 放大：按固定倍率递增，例如 `x1.2`
- 缩小：按固定倍率递减，例如 `/1.2`

若实现成本低，可补充滚轮缩放；若会明显扰动当前点选逻辑，则不作为本轮强制项。

如果补充滚轮缩放，要求：

- 仅桌面端启用
- 需做 `preventDefault`
- 仍受 `minZoom/maxZoom` 限制
- 不得破坏绘制态和校准态的点选行为

### 6.4 点击坐标换算

由于本轮引入了 `zoom + pan`，画布点击取点逻辑必须更新：

- 屏幕坐标
  -> 容器内坐标
  -> 逆向扣除 `panX/panY`
  -> 按 `zoom` 反算到原始场景坐标

这一条对以下场景都必须成立：

- 校准点拾取
- 绘制多边形
- 选中已有图形

由于本轮采用 `viewBox` 方案，坐标换算应以当前 `viewBox` 和容器尺寸为基准，而不是按 CSS transform 逆推。

## 7. 审核预览页整改

### 7.1 目标

选位审核页的场景预览不再只是“被动塞进去的一张静态图”，而是具备只读视口控制的真实预览器。

### 7.2 能力边界

审核预览页采用只读模式：

- 支持适配画布
- 支持放大
- 支持缩小
- 支持拖拽平移
- 支持重置视图

不支持：

- 绘制
- 删除图形
- 改属性
- 改底图

### 7.3 与编辑器的关系

审核预览页复用同一套视口逻辑和底层场景展示组件，但通过 `readOnly` 或等价参数关闭编辑行为。

这样可以保证：

- 编辑器与审核页的观看体验一致
- 一套修复同时覆盖两端
- 后续若要扩展销售端只读地图，也能复用

## 8. 信息区稳定化

### 8.1 右栏宽度

编辑器右侧“当前草稿 + 属性”区域采用稳定宽度：

- 桌面端固定宽度
- 不允许因长文件名、长 UUID、长描述文案被压成逐字换行

### 8.2 文件名显示

“底图文件”一行改为：

- 默认单行省略
- hover 显示完整文件名
- 若无底图则显示 `未上传`

### 8.3 修订号显示

“当前修订”默认显示短形式：

- 例如前 8 位或 `xxxx...yyyy`

完整值通过 tooltip 查看。

### 8.4 描述文案

右栏底部说明文案保持简短，不使用会把窄列撑坏的长段文本。

必要时拆成两行短句，而不是一整段硬塞。

## 9. 组件边界

### 9.1 SceneCanvas

负责：

- 渲染背景图与图形
- 承载视口变换
- 处理点击坐标换算
- 处理拖拽平移
- 触发适配画布和重置视图

不负责：

- 上传逻辑
- 发布逻辑
- 业务属性编辑

### 9.2 SceneEditorPage

负责：

- 管理上传、保存、发布、校准等业务动作
- 管理当前草稿状态
- 管理画布视口 UI 控件
- 把背景图和视口状态传给 `SceneCanvas`

### 9.3 SelectionScenePreview

负责：

- 拉取已发布场景展位
- 以只读模式挂载预览地图
- 暴露只读视口工具

## 10. 性能说明

### 10.1 本轮性能预期

本轮默认目标仍是：

- 真实底图可加载
- 中小规模 Booth 图元可流畅缩放和平移

本轮不单独立性能专项，但实施时需要避免明显卡顿。

### 10.2 可接受的轻量优化

如果在实现过程中遇到以下场景：

- 底图较大
- 图元较多
- 拖拽平移有肉眼可见卡顿

可接受的轻量优化包括：

- 上传后使用更适合前端展示的底图尺寸
- 拖拽更新使用 `requestAnimationFrame` 节流
- 减少不必要的 React 重渲染
- 对视口控制相关计算做 `useMemo` / `useCallback` 稳定化

### 10.3 本轮不强制的性能专项

以下不作为本轮硬要求：

- 自动底图降采样流水线
- 多级瓦片切图
- WebGL 渲染
- 大规模对象虚拟化
- 后端图形缓存服务

## 11. 测试与验收

### 11.1 前端单测

至少补充：

- `fit-to-canvas` 计算在有背景图时返回合理缩放与偏移
- `fit-to-canvas` 在仅有图形时返回合理缩放与偏移
- 放大 / 缩小按钮能正确更新 `zoom`
- 平移状态更新不会破坏原始图形数据
- 上传前大小校验在 `>10MB` 时阻止请求

### 11.2 浏览器验收

至少覆盖：

- 上传小于 `10MB` 的真实底图成功
- 上传大于 `10MB` 的文件时前端直接提示
- 编辑器打开真实底图后默认完整适配
- 编辑器能放大、缩小、拖拽和平移
- 审核预览页能放大、缩小、拖拽和平移
- 长文件名不会把右栏压坏

### 11.3 已知本轮不处理

- 超大 PDF 多页导航
- 背景图旋转
- 背景图裁切
- 鼠标滚轮缩放手感细调

## 12. 结论

本轮整改采用“局部加固，不重构重写”的策略：

- 上传上限提到 `10MB`
- 上传前补大小提示和前端拦截
- 为编辑器和审核预览页补统一视口模型
- 默认自动适配真实底图
- 提供缩放、平移、重置视图
- 修复右栏在真实文件名下的布局稳定性

这样可以把现有场景能力从“工程可演示”推进到“真实底图可工作”的状态，为下一阶段继续做更强的馆图编辑体验打基础。
