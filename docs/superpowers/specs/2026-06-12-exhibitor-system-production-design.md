# 中国国际体育用品博览会展商系统生产设计方案

## 1. 设计目标

中国国际体育用品博览会展商系统定位为真实上线可用的展商全生命周期运营系统，而不是展示型报名网站。

系统需要覆盖展商从注册报名、资质审核、面积档位购买、合同签署、付款确认、展位选择、后台审核、服务办理、财务发票、数据归档到历史复用的完整业务闭环。

核心建设目标：

- 支撑多届展会运营。
- 防止展位重复销售、重复锁定和长期占用。
- 保证订单、合同、付款、展位之间的数据一致。
- 支持展商自主选位，但必须经过销售或管理员最终审核。
- 支持线上支付和线下转账两类付款方式。
- 所有关键业务操作可追溯、可审计、可回滚或作废。
- 支持完整生产系统所需的权限、日志、通知、统计和运维能力。

## 2. 核心业务原则

系统主流程采用“先规划展位库存，再由展商选择平米数，签约付款后再选择具体位置”的模式。

展位资源在展商报名和选位前由主办方或展位规划人员完整规划，包括展会、展馆、展区、展位编号、展位面积、展位类型、价格和状态。展商报名参加展会时，先基于后台配置的标准面积档位选择参展平米数，系统按每平米单价计算费用，销售或管理员确认订单后生成合同。展商签署合同并完成付款，财务确认收款后，系统才允许其进入具体位置选择。展商可以选择一个或多个展位，提交后由销售或管理员审核确认。

这一模式将展位库存、面积交易和展位确认清晰拆开：

- 订单和合同的核心标的是展会、展区或品类、标准面积档位、单价和总价。
- 具体展位在业务开始前已经规划好，但展商只有付款确认后才能选择具体位置。
- 财务确认收款后，展商的具体选位才能进入正式锁定和审核。
- 展位选择必须受已购面积、展区范围、展位状态和锁位规则约束。

## 3. 总体业务流程

```text
主办方规划展会、展馆、展区和全部展位资源
-> 配置标准面积档位、单价和展位状态
-> 展商注册/登录
-> 提交企业资料和参展报名
-> 主办方审核报名
-> 展商选择展区/品类和标准面积档位
-> 系统按每平米单价计算费用
-> 销售/管理员确认订单
-> 系统生成合同
-> 展商签署合同并付款
-> 财务确认收款
-> 系统开放具体位置选择
-> 展商选择一个或多个展位
-> 系统校验面积合计、展区范围和展位状态
-> 系统锁定展位并提交审核
-> 销售/管理员审核确认
-> 展位正式落位
-> 展商按服务开放条件办理参展事项
-> 订单、合同、付款、展位、服务资料归档
```

关键约束：

- 展商必须完成财务确认收款后，才能进入选位。
- 展商可以选择多个展位，面积合计必须等于已购标准面积档位。
- 多个展位不强制相邻，但必须满足展区、状态和面积规则。
- 展商提交选位后，选位申请进入待审核状态，关联展位进入锁定中状态。
- 锁位时限由管理员灵活配置；超时后系统原子执行超时处理，选位申请置为已超时，关联展位恢复可选，订单选位资格回到可选位。
- 展位最终确认必须由销售或管理员审核通过。

## 4. 系统模块设计

### 4.1 展会与展位资源管理

管理多届展会、展馆、展区、展位、展位图、展位状态、标准面积档位、价格规则和锁位时限。展位资源必须在展商选择平米数和具体位置前完成规划，作为后续面积选择、价格计算和位置选择的基础库存。

主要能力：

- 创建和维护展会届次。
- 配置报名时间、付款时间、选位时间、服务办理时间。
- 配置展馆、展区、展位编号、面积、类型、状态和坐标信息。
- 配置标准面积档位，如 9 平方米、18 平方米、36 平方米。
- 配置展区或展位类型的每平米单价。
- 提供展商可选择的展位库存和面积档位依据。
- 提供档位可拼性校验，确保标准面积档位能够由当前可选展位组合精确满足。
- 配置默认锁位时长，支持管理员对单个选位申请延期或释放。

### 4.2 展商报名与审核

展商完成注册后提交企业资料、联系人、参展品类和资质材料。主办方审核通过后，展商才能进入面积档位选择和订单流程。报名审核通过的参展品类作为订单可选品类和可选展区的上限范围。

主要能力：

- 展商注册和登录。
- 企业资料维护。
- 参展报名提交。
- 资质材料上传。
- 报名资料完整性校验。
- 主办方审核、驳回和复审。
- 审核意见和操作记录留存。

### 4.3 面积订单与合同管理

参展订单是系统核心交易单。订单记录展商购买的面积权益，而不是一开始就绑定具体展位。

主要能力：

- 展商在报名审核通过的品类和展区范围内选择订单展区/品类。
- 展商选择标准面积档位。
- 系统按每平米单价计算费用。
- 支持面积费用、服务费、优惠金额和调整项。
- 销售或管理员确认订单。
- 订单确认后生成合同。
- 合同支持模板、版本、签署、变更、作废和归档。
- 合同金额或面积档位变化时必须走合同变更或重签流程，不能直接覆盖原合同。
- 订单进入选位后禁止直接修改面积档位；如需调整面积，必须先关闭或取消有效选位申请，再进入合同变更流程。

### 4.4 收款、付款与发票

系统同时支持线上支付和线下转账。无论使用哪种方式，都必须形成统一的收款记录。

主要能力：

- 线上支付下单、回调和自动确认。
- 线下转账凭证上传。
- 财务人工核对到账。
- 支持待支付、待财务确认、部分确认、已确认、确认失败、已退款、已冲正和已作废状态。
- 财务确认收款后，订单进入已付款状态。
- 只有已付款订单才能开放选位资格。
- 发票申请、开票处理和开票状态维护。
- 财务记录不允许物理删除，只能作废、冲正或退款。

### 4.5 展商自主选位与后台审核

展商在付款确认后进入选位。系统校验展位状态和面积规则，提交后进入锁定和审核流程。

主要能力：

- 付款后开放选位入口。
- 展商按订单已购买展区范围内的展馆、展区、面积、状态筛选展位，不允许跨订单展区选位。
- 展商可以选择一个或多个展位。
- 实时展示已选面积和应选面积。
- 面积不足或超出时禁止提交。
- 提交时对所有展位进行申请级整体锁定，共享同一个锁位截止时间。
- 锁定成功后选位申请进入待审核状态，关联展位进入锁定中状态。
- 销售或管理员审核通过后展位正式确认。
- 审核驳回、锁位超时或管理员释放时，展位恢复可选。
- 订单退款完成或合同作废影响已确认展位时，系统关闭选位资格并生成展位释放待办，不自动释放展位；管理员或有权限人员人工确认释放并记录原因。

### 4.6 展商服务中心

服务中心按服务事项配置开放条件，用于办理参展前、中、后所需事项。每类服务可配置前置条件，包括报名通过、订单生成、付款确认、展位确认等。广告类服务可早于展位确认开放，施工、楣板、用电等依赖具体位置的服务可要求展位确认后开放。

服务类型包括：

- 证件服务：展商证、施工证、车辆证、布撤展证。
- 楣板信息：标准展位公司名称、英文名称、展位名称。
- 用电网络：额外用电、网络、水、气、压缩空气。
- 家具租赁：桌椅、展柜、洽谈桌、电视、灯具。
- 广告服务：会刊广告、现场广告、LED 屏、资料袋广告。
- 特装搭建：施工图、效果图、搭建公司资质、安全承诺书。
- 物流运输：展品运输、进馆时间、货车信息、物流服务。
- 费用服务：服务订单、付款凭证、发票申请。

主要能力：

- 服务事项配置。
- 服务开放条件配置。
- 服务办理粒度配置，支持按订单办理和按展位办理。
- 办理截止时间配置。
- 必填字段和附件配置。
- 服务申请提交。
- 服务中心人员审核。
- 收费服务生成服务订单。
- 服务付款和财务确认。
- 服务执行状态更新。
- 服务记录归档至展商档案。

### 4.7 消息通知

系统需要提供站内信，并预留短信和邮件接口。

通知场景包括：

- 报名审核通过或驳回。
- 订单待销售确认。
- 合同待签署。
- 线下付款待财务确认。
- 付款确认成功。
- 选位资格开放。
- 选位审核通过或驳回。
- 锁位即将超时。
- 选位草稿即将到期或已清除。
- 订单作废。
- 退款进度。
- 合同变更。
- 展位强制释放。
- 发票开票完成。
- 服务申请审核结果。
- 服务申请待补充资料。

### 4.8 报表统计

系统需要支持运营、销售、财务和服务多维统计。

统计维度包括：

- 报名数量和审核通过率。
- 展区销售面积和剩余面积。
- 订单金额和收款金额。
- 线上支付和线下转账占比。
- 展位销售率和展区热度。
- 合同签署进度。
- 发票处理进度。
- 服务事项办理进度。
- 历史展商复购和复参情况。

### 4.9 系统管理与安全

生产系统必须包含权限、日志、备份、审计和基础安全能力。

主要能力：

- 用户管理。
- 角色管理。
- 菜单和按钮权限。
- 数据权限。
- 系统参数配置。
- 操作日志。
- 登录日志。
- 关键数据变更审计。
- 数据备份和恢复策略。
- 文件上传安全校验。
- 敏感操作二次确认或审批。

## 5. 统一术语与核心状态设计

### 5.1 统一术语表

| 术语 | 统一定义 |
| --- | --- |
| 展区/品类 | 报名审核通过的经营或参展品类映射到可购买展区。订单只能在该范围内选择展区或品类。 |
| 面积费用 | 标准面积档位乘以每平米单价得到的主费用。 |
| 服务费 | 参展订单或服务订单中额外收取的服务类费用。 |
| 优惠金额 | 销售或管理员按权限审批后给予的减免金额。 |
| 调整项 | 因业务调整产生的加收或减免费用，必须记录原因。 |
| 订单总价 | 面积费用 + 服务费 + 调整项 - 优惠金额。 |
| 选位资格 | 订单是否允许创建新的选位申请。 |
| 选位申请 | 展商针对某一订单提交的一组展位选择和审核记录。 |
| 撤销 | 取消选位申请或取消订单与展位的绑定关系。 |
| 释放 | 将展位运行状态恢复为可选。 |

付款状态统一使用：待支付、待财务确认、部分确认、已确认、确认失败、已退款、已冲正、已作废。

### 5.2 报名状态

```text
草稿
-> 待审核
-> 审核通过
-> 驳回
-> 重新提交
```

规则：

- 草稿状态可编辑。
- 待审核状态不可由展商直接修改。
- 驳回必须填写原因。
- 审核通过后才允许创建参展订单。

### 5.3 订单状态

```text
待销售确认
-> 待签合同
-> 待付款
-> 已付款
-> 已完成
```

异常状态：

```text
部分付款
已作废
退款中
已退款
合同变更中
```

规则：

- 销售或管理员确认后才能生成合同。
- 已付款状态必须来自财务确认后的收款记录。
- 部分付款不能开放选位。
- 作废、退款、合同变更必须记录原因和操作人。
- 已完成由展会归档或管理员完成归档触发，不因付款或选位立即完成。
- 部分付款可继续付款至已付款，也可进入退款或作废流程。
- 合同变更中期间冻结付款、选位和展位释放操作；变更完成后按新合同状态回到待付款或已付款。
- 退款中可从已付款或已完成进入；退款完成后订单进入已退款，系统关闭选位资格并生成展位释放待办。

### 5.4 付款状态

```text
待支付
-> 待财务确认
-> 已确认
```

异常状态：

```text
部分确认
确认失败
已退款
已冲正
已作废
```

规则：

- 线上支付可由支付回调自动确认。
- 线下转账必须由财务人工确认。
- 部分确认可继续确认至已确认，也可进入已退款、已冲正或已作废。
- 确认失败后退回展商重新提交凭证或重新支付。
- 财务记录不允许物理删除。

### 5.5 选位资格状态 SelectionEligibility

```text
未开放
-> 可选位
-> 暂停中
-> 已关闭
```

规则：

- 未付款订单保持未开放。
- 已付款订单进入可选位。
- 选位申请草稿不暂停选位资格，不锁定展位。
- 选位申请提交进入待审核后，选位资格暂停，避免同一订单并发创建多个有效申请。
- 选位申请已驳回、已超时或已取消后，订单选位资格回到可选位。
- 退款完成、合同作废或订单作废后，选位资格进入已关闭。
- 合同变更中时，选位资格进入暂停中，变更完成后按订单状态重新计算。
- 选位资格进入暂停中时必须记录 pause_reason，取值至少包括 selection_pending 和 contract_change。

### 5.6 选位申请状态 BoothSelection.status

```text
草稿
-> 待审核
-> 已确认
```

结束状态：

```text
已驳回
已超时
已取消
```

规则：

- 草稿不锁定展位。
- 草稿默认保留 24 小时，超时后系统自动清除草稿；管理员可按展会配置调整草稿 TTL。
- 提交后进入待审核，并对关联展位执行申请级整体锁定。
- 审核通过后进入已确认，关联展位变为已确认。
- 审核驳回后进入已驳回，关联展位释放为可选，订单选位资格回到可选位。
- 超时后进入已超时，关联展位释放为可选，订单选位资格回到可选位。
- 草稿和待审核可以由展商主动取消或管理员取消后进入已取消；已确认选位申请不能直接取消，必须走展位释放待办。
- 待审核取消后，关联展位释放为可选，订单选位资格回到可选位。
- 同一订单同一时间只能存在一个草稿或待审核状态的有效选位申请。

### 5.7 展位状态

规划初始化状态只允许：

```text
可选
预留
禁用
```

运行时状态为：

```text
可选
锁定中
已确认
预留
禁用
```

规则：

- 同一展位同一时间只能被一个有效选位申请锁定。
- 展位状态变更必须记录操作人、时间、原状态、新状态和原因。
- 已确认展位释放必须走管理员操作或业务审批。
- 选位申请待审核时，关联展位从可选变为锁定中。
- 选位申请已确认时，关联展位从锁定中变为已确认。
- 选位申请已驳回、已超时或已取消时，关联展位从锁定中回到可选。
- 释放是状态变更动作，不作为展位稳定状态。

### 5.8 服务订单状态 ServiceOrder.status

```text
待付款
-> 已付款
-> 已完成
```

异常状态：

```text
已退款
已作废
```

规则：

- 服务订单状态独立于参展订单，不参与选位资格计算。
- 收费服务申请审核通过后生成待付款服务订单。
- 服务订单收款确认后进入已付款。
- 服务事项执行完成并归档后进入已完成。
- 退款后进入已退款，作废后进入已作废。

## 6. 核心数据对象

### 6.1 展会 Event

表示一届展会。保存展会名称、年份、举办时间、报名时间、付款时间、选位时间、服务办理时间、默认锁位时长和状态。

### 6.2 展馆 Pavilion、展区 Zone、展位 Booth

展馆和展区用于组织展位资源。展位保存编号、面积、类型、所属展馆、所属展区、状态、坐标或图形信息、是否可选等字段。

### 6.3 展商 Exhibitor

表示参展企业主体。保存企业名称、统一社会信用代码、联系人、账号绑定信息和历史参展记录。

### 6.4 报名申请 Registration

表示某展商对某届展会的报名。报名通过后允许创建参展订单。报名申请记录审核通过的参展品类，并作为后续订单可选品类和可选展区的约束范围。

### 6.5 参展订单 ParticipationOrder

核心交易对象。记录 EventId、展商、报名申请、展区/品类、标准面积档位、每平米单价、面积费用、服务费、优惠金额、调整项、订单总价和订单状态。

参展订单不直接等同于具体展位。具体展位在付款后通过选位申请绑定。

规则：

- 同一展商同一届展会允许存在多个参展订单。
- 每个订单独立拥有合同、付款记录、选位资格和选位申请。
- 订单展区/品类必须落在报名审核通过的品类和展区范围内。
- 订单进入选位后，不允许直接修改面积档位。
- 订单已付款状态由付款记录聚合计算：已确认付款金额合计大于或等于订单总价时，订单进入已付款。
- 已确认付款金额大于 0 且小于订单总价时，订单进入部分付款。

### 6.6 合同 Contract

合同关联参展订单。合同内容来自订单、展商、展会和费用信息。合同签署后不可直接覆盖，变更应生成新版本或变更记录。

### 6.7 付款记录 Payment

付款记录关联订单。支持线上支付和线下转账。线下付款需要凭证文件和财务确认状态。

### 6.8 选位申请 BoothSelection

选位申请关联已付款订单。记录 EventId、订单、展商、所选展位列表、合计面积、锁定开始时间、锁定截止时间、申请状态、协助人、审核人、审核时间和审核意见。

规则：

- 一个订单同一时间只能有一个有效选位申请。
- 一个选位申请可以包含多个展位。
- 展位面积合计必须等于订单面积档位。
- 锁位截止时间为申请级统一截止时间。
- 销售允许审核自己协助过的选位申请，但系统必须记录协助人、审核人、审核时间和审核意见。

### 6.9 展位锁定记录 BoothLock

记录展位锁定明细。每个被选择的展位生成一条锁定记录，关联 EventId、订单、选位申请和展位。

规则：

- 锁定、确认、释放、超时都要保留记录。
- BoothLock 继承选位申请的锁位截止时间，不允许单个展位单独到期。
- 审核通过后，锁定转为正式确认。
- 驳回或超时后，关联展位恢复为可选。

### 6.10 服务申请 ServiceApplication

服务申请关联展商、展会、订单和可选的目标展位。不同服务类型可配置开放条件、办理粒度、字段、附件、收费规则和审核流程。

规则：

- 办理粒度支持按订单和按展位。
- 广告、会刊等服务可按订单或展商办理，不强制绑定具体展位。
- 楣板、用电、搭建等依赖位置的服务应按目标展位办理。

### 6.11 服务订单 ServiceOrder

服务订单是收费服务事项产生的独立财务对象，不能复用参展订单。

服务订单记录 EventId、展商、服务申请、服务类型、目标订单、可选目标展位、服务费、优惠金额、调整项、订单总价、付款状态和开票状态。

规则：

- 服务订单与参展订单分别记账。
- 服务订单收款确认由财务人员处理。
- 服务订单付款不影响参展订单的选位资格。

## 7. 角色与权限

### 7.1 展商账号

可完成注册登录、企业资料维护、报名提交、查看审核结果、选择面积档位、查看订单合同、付款或上传凭证、付款后选位、查看选位审核结果、办理服务事项。

限制：

- 不能修改已确认订单金额。
- 不能跳过财务确认进入选位。
- 不能释放或占用他人展位。
- 不能修改后台审核结果。

### 7.2 系统管理员

负责技术运维和系统安全，管理账号、角色、权限、系统参数、登录日志、操作日志、数据备份、恢复策略和安全配置。系统管理员不作为默认业务审核人，不直接替代财务确认、选位审核和服务审核；确需介入业务数据时必须保留独立操作记录。

### 7.3 主办方管理员

负责业务运营管理，管理展会配置、报名审核、订单审核、合同管理、展位审核、释放待办、服务协同和统计数据。主办方管理员可处理跨部门业务流程，但财务确认仍由财务角色负责。

### 7.4 招商销售人员

跟进展商、查看报名、确认参展面积和价格、发起订单确认、协助展商选位、审核选位申请、维护客户关系。销售允许审核自己协助过的选位申请，但系统必须记录协助人、审核人、审核时间和审核意见。

### 7.5 展位规划人员

维护展馆、展区、展位、展位图、单价规则、标准面积档位和锁位时限。可以预留、禁用、释放展位，但释放已确认展位必须记录原因。

### 7.6 财务人员

核对线下付款、确认到账、处理退款、开票状态和收款记录归档。

限制：

- 不能修改展位资源。
- 不能直接修改合同核心金额。
- 不能绕过订单状态确认收款。

### 7.7 服务中心人员

配置和处理证件、楣板、用电、家具、搭建等服务事项，审核服务申请，更新执行状态。

限制：

- 不能修改参展订单主金额。
- 不能修改展位销售状态。

### 7.8 权限控制原则

```text
报名审核：主办方管理员
价格调整：销售可发起，管理员可审批
合同生成：订单确认后系统生成，管理员可重生成或变更
收款确认：财务专属
服务订单收款确认：财务专属
发票办理：财务人员
退款处理：财务人员发起或处理，管理员按业务规则审批
选位审核：销售或管理员
展位释放待办处理：主办方管理员或有权限的展位规划人员
展位资源维护：展位规划人员或管理员
服务办理：服务中心人员
日志查看：管理员或主办方管理员
```

## 9. 关键异常流程

### 9.1 报名驳回

主办方驳回报名时必须填写原因。展商收到通知后修改资料并重新提交。

### 9.2 价格调整

销售或管理员调整价格、优惠金额或调整项时，必须填写调整原因。超过权限范围的调整需要管理员审批。合同生成后金额或面积档位变化必须走合同变更或重签。

订单进入选位后禁止直接修改面积档位。若必须修改面积档位，应先关闭或取消草稿、待审核状态的有效选位申请；如已有已确认展位，应先生成展位释放待办并由管理员完成人工释放，再进入合同变更流程。

### 9.3 付款异常

线下付款凭证金额不符、未到账或无法确认时，财务可将付款记录置为确认失败，并填写原因。展商可重新提交凭证或重新支付。部分确认可继续确认至已确认，也可进入退款、冲正或作废流程。部分确认不能开放选位。

### 9.4 选位超时

展商提交选位后，系统按申请级配置设置统一锁位截止时间。超时未审核时，系统定时任务必须原子执行：选位申请置为已超时，关联展位从锁定中恢复为可选，订单选位资格回到可选位，并记录系统操作日志。

### 9.5 选位驳回

销售或管理员驳回选位申请时，必须填写原因。被驳回申请进入已驳回，关联展位从锁定中恢复为可选，订单选位资格回到可选位，展商可重新创建选位申请。

### 9.6 展位释放和撤销

撤销指取消选位申请或取消订单与展位的绑定关系。释放指将展位运行状态恢复为可选。

已确认展位释放必须由管理员或有权限人员人工操作，并记录原因。若因退款完成、合同作废或业务变更影响已确认展位，系统只关闭选位资格并生成展位释放待办，不自动释放展位。管理员或有权限人员处理待办后，系统同步更新订单、合同、选位申请、BoothLock 和展位状态。

### 9.7 合同变更

合同签署后发生金额、面积、展区或关键条款变化时，不能覆盖原合同。系统应生成合同新版本或合同变更记录。

订单进入合同变更中后，付款、选位和展位释放操作全部冻结。变更完成后，若新合同仍需付款，订单回到待付款；若财务确认金额已满足新合同，订单回到已付款并重新计算选位资格。涉及面积档位变化时，必须先关闭有效选位申请；涉及已确认展位时，必须先完成人工释放待办。

合同变更进入时若存在待审核选位申请，该申请暂停审核，锁位截止时间暂停计时。变更完成后，若面积和展区规则未变化，恢复审核并继续剩余锁位时间；若面积或展区规则变化，必须取消原待审核申请，关联展位恢复可选，订单按新合同重新开放选位资格。

新合同金额低于已确认付款金额时，必须由财务先按退款和冲正流程处理差额退款；差额处理完成后，订单才能回到已付款或进入后续选位流程。

### 9.8 退款和冲正

退款或冲正必须由财务处理，并关联原付款记录。退款中可从已付款或已完成进入。退款完成后，订单进入已退款，选位资格进入已关闭。

退款影响已确认展位时，系统生成展位释放待办，不自动释放展位；管理员或有权限人员人工处理释放并记录原因。

## 10. 生产风险与防控

系统需要重点防控以下风险：

- 同一展位被重复锁定或重复确认。
- 订单金额和合同金额不一致。
- 付款未确认却开放选位。
- 合同变更后旧合同仍被误用。
- 退款后展位未释放。
- 选位超时但展位仍被占用。
- 销售越权调整价格。
- 财务记录被删除或覆盖。
- 服务申请绕过付款或审核。

防控措施：

- 展位锁定和确认必须使用事务或等效并发控制。
- 订单、合同、付款、选位之间建立状态校验。
- 关键财务数据只能作废、冲正或退款，不允许物理删除。
- 展位状态变更全部进入审计日志。
- 价格调整和合同变更必须保留版本记录。

## 11. 建设顺序建议

系统目标是完整生产系统，不按功能裁剪上线范围。但工程建设需要按依赖关系推进和验收。

建议顺序：

```text
1. 建立业务主数据
   展会、展馆、展区、展位、展商、角色权限。

2. 建立交易主链路
   报名、面积档位、价格、订单、合同、付款。

3. 建立资源履约链路
   选位资格、展位锁定、选位审核、展位确认。

4. 建立服务和运营能力
   服务中心、发票、退款、消息通知、报表。

5. 建立生产保障能力
   日志审计、备份、安全加固、压测、上线演练。
```

这些步骤是实施和验收顺序，不代表功能分期或范围删减。最终交付目标是完整可落地的生产系统。

## 12. 与原业务流程的主要调整

原业务说明中的总体方向合理，但需要进一步明确展位资源的前置规划，以及选平米数和选具体位置之间的顺序。真实业务中，主办方通常先规划好展会、展馆、展区和全部展位资源；展商先选择参展平米数并完成合同付款；付款确认后，展商再从已规划的展位资源中选择具体位置。

正式设计调整为：

```text
展位资源规划
-> 展位库存、面积档位和价格配置
-> 展商报名审核
-> 展商选择展区/品类和标准面积档位
-> 订单和合同
-> 签约付款
-> 财务确认
-> 展商选择具体位置并提交选位申请
-> 系统锁位
-> 后台审核确认展位
-> 服务中心
```

该流程不采用“付款后才产生展位”的逻辑。展位从一开始就已经存在，付款确认只是展商进入具体位置选择、正式锁定和确认展位的前置条件。

需要避免的旧理解是：

```text
报名审核
-> 随意选择面积
-> 订单和合同
-> 签约付款
-> 财务确认
-> 再临时生成或规划展位
```

调整原因：

- 真实业务中展位资源通常最先规划完成。
- 展商先选择参展平米数，签约付款后再选择具体位置。
- 财务确认作为选位门槛，可以防止无效占位。
- 后台审核作为最终确认，可以保留主办方对展位布局和运营的控制权。

## 13. 合同签订前必须确认事项

以下事项会影响工期、报价、接口和实施边界，必须在项目合同或实施方案签订前确认。

### 13.1 已采用的默认方案

- 展位图初始形态：采用列表视图 + 简单平面图。后台维护展位坐标、编号、面积和状态；不在首版交付完整可视化展位图编辑器。
- 价格审批规则：采用优惠比例分档审批。0% 至 5% 为销售提交后由主办方管理员单人审批；超过 5% 为销售提交后先由主办方管理员审批，再由系统管理员或更高权限角色复核。具体比例和复核角色可在系统参数中配置。
- 数据库部署方式：不进行历史数据迁移，新系统从空白启动。由采购方提供 PostgreSQL JDBC 连接信息，应用方在该数据库内申请独立 schema（默认命名 exhibitor_sys）部署所有业务表，不与其他业务共用 schema 命名空间。

### 13.2 仍需商务和实施确认

- 合同签署方式：电子签章平台、上传盖章扫描件，或两者都支持。
- 线上支付渠道：微信、支付宝、银联、银行网关或聚合支付。
- 发票类型：普票、专票、电子发票和纸质发票的支持范围。
- 消息通知渠道：站内信、短信、邮件、微信公众号模板消息。
- 数据权限粒度:销售是否只能看自己的客户，或可看全部展商。
